# AutoRepair AI Hosting Beta 0.20.2

## 0.20.2：MariaDBの実バージョン表示を使う互換性判定

- WordPressの省略版DB番号ではなく、DBサーバー自身の `SELECT VERSION()` 結果でMySQL／MariaDBを判定します。

## 0.20.1：MariaDB 10.5+ の検証対象化

- MySQL 8.4 と MariaDB 10.5 の隔離バックアップ・同一サイト復元・クローンリハーサルをGitHub Actionsで実行します。
- 対象DBは、MySQL 8.x または MariaDB 10.5以上の InnoDB テーブルに限定します。

## 0.20.0：導入前確認と保守担当者の安全な操作範囲

- 画面からの全体バックアップを、書き込み停止の確認付きで予約できます。
- PHP・MySQL・ZipArchive・保管先・隔離リハーサルの前提を一覧で確認できます。
- 「AutoRepair AI 保守担当者」ロールは閲覧と隔離リハーサルのみ可能で、設定・本番復元は管理者に限定します。

## 0.19.0：復旧リハーサルを予約し、影響範囲を確認

- 隔離復元テストをWP-Cronで予約し、画面待ちを減らします。対象は隔離環境のみで、本番復元は実行しません。
- 週1回の定期リハーサルと、不合格時の管理者メール通知を任意で有効化できます。
- 保存ポイントに対して、復元対象のDB・ファイル・保存時の環境情報を表示します。既存の保存ポイントに環境情報がなければ「記録なし」と表示します。

## 0.18.0：復旧リハーサルを運用画面から開始

- 保存ポイントごとに、確認付きの「復旧リハーサルを開始」操作を追加。本番サイトは変更せず、隔離環境でのみ実行します。
- 復旧後にトップページ HTTP 応答・管理権限・DB 接続を自動確認。メールとフォームは送信せず、手動確認として記録します。
- 復元信頼度スコアの内訳と、更新前セーフティゲートの状態を明示します。

## 0.16.0：製品検証を見える化

- 「最新検証結果」画面を追加。GitHub Actionsの直近実行を参照し、確認済み・未検証・準備中を分けて表示します。
- 隔離Docker環境で、0.15.0からの実ファイル更新、登録データの維持、バックアップ、破損拒否、復元、更新ロールバックを検証します。
- 大量サイトの利用数同期は100・500・1,000サイト相当を含む手動負荷計測にしました。Stripeはテストモード設定時のみ、Paddleは準備中です。

## 0.15.1：3つの入口で迷わない運用画面

- **① 守る**：バックアップ、隔離復元テスト、更新前リスクをまとめて確認
- **② 対応する**：緊急モード、障害・復旧履歴、復旧後チェックを一か所に集約
- **③ 広げる**：接続サイトの重要度、顧客向け閲覧、グループ・料金へ進む入口

「緊急モード」は、保存ポイントの確認 → 隔離復元テストの確認 → 本番復元 → 復旧後チェック、の順に表示します。本番復元は自動実行しません。

復旧後チェックは、トップページ・管理画面・DB・メール・フォームを記録します。メール送信やフォーム送信、外部連携は隔離復元テストの範囲外なので、必要なサイトだけ実サイトで確認してください。
